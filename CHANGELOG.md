# History

- 2026-10-14: searchable mapping labels (requires TaxoStore API 1.1.0 for searching mappings; with previous versions, lookup just ignores mappings):
  - `@myrmidon/taxo-store-api` (1.2.0):
    - `TaxoStoreNodeMapping` has a new `filteredLabel` property.
    - `TaxoStoreNodeFilter` has a new `filteredMappingLabel` property, matching any part of the filtered label of any mapping of the node. When `filteredLabel` is also set, the two are combined with OR.
  - `@myrmidon/taxo-store-editor` (1.2.0):
    - `TaxoStoreNodeMappings` has a new filtered label field. When empty, it defaults to the label, as for nodes; picking an item from a lookup clears it.
    - the label filter of `TaxoStorePagedTreeService` and `TaxoStorePagedListService` (used by `TaxoStoreEditor` for its tree and list views) matches both the filtered label of nodes and the filtered labels of their mappings.
  - `@myrmidon/taxo-store-picker` (1.1.0): `TaxoStoreLookupService` looks up nodes by both their filtered label and the filtered labels of their mappings (e.g. aliases).
- 2026-10-13: flat trees and node mappings (requires TaxoStore API 1.0.0):
  - `@myrmidon/taxo-store-api` (1.1.0):
    - `TaxoStoreTree` has a new `flat` property, true when all the nodes of the tree are root nodes.
    - added `TaxoStoreNodeMapping` (`scope`, `target`, `label`) and `TaxoStoreNode.mappings`. When saving a node, an array of mappings (even when empty) replaces all the mappings of that node, while null or undefined mappings leave them untouched.
    - `getNode`, `getNodeFromKey`, `getRootNodes`, `getChildNodes`, `getDescendantNodes`, `getAncestorNodes` have a new optional `includeMappings` parameter (false by default), and `TaxoStoreNodeFilter` a new `includeMappings` property.
    - `TaxoStoreNodeFilter` has new `mappingScope` and `mappingTarget` properties, to find nodes from their mappings.
  - `@myrmidon/taxo-store-editor` (1.1.0):
    - `TaxoStoreEditor` displays a flat tree as a paged list rather than as a tree, with its nodes key and label. After adding or editing a node, the list moves to the page of that node and highlights it.
    - ⚠️ `TaxoStoreEditor`: removed the add sibling button next to each node, and the corresponding `addSiblingNode` method. The button suggested that the new node would be added after that node, while nodes are sorted by key. It is replaced by a single button at the top, which adds a node at the root level (`addRootNode` method). The add child button is still there (except in flat trees), as it only defines the parent of the new node.
    - `TaxoStoreNodeEditorDialog` now has two tabs: general (the previous editor) and mappings. It is wider (720px) to fit the mappings table. The node cannot be saved while a mapping is being edited. Mappings which were not loaded with the node being edited are saved only when changed.
    - added `TaxoStoreNodeMappings` to edit the mappings of a node, either manually or via lookup. Lookup is available when lookup providers are configured in `RamStorageService` under `LOOKUP_CONFIGS_KEY` (see README); picking an item from a lookup sets scope (lookup provider ID), target (item ID) and label (item name).
    - added `TaxoStorePagedListService` (adapter for the paged list store) and `toTaxoStoreTreeNode`.
    - new peer dependency: `@myrmidon/cadmus-refs-lookup`.
  - `@myrmidon/taxo-store-picker` (1.0.2): updated peer dependencies.
  - app: configured VIAF lookup for node mappings (added `@myrmidon/cadmus-refs-viaf-lookup`); the trees list in the editor page marks flat trees.
- 2026-10-13: updated Angular and packages.
- 2026-10-03: aligned to TaxoStore API 0.0.9 fixes:
  - removed `@myrmidon/cadmus-part-taxo-store-nodes` (moved elsewhere), including its leftover references in `tsconfig.json`.
  - `@myrmidon/taxo-store-api`:
    - `addNode` and `addTree` now get the ID from the response body, as returned by the API. This removes the previous workaround getting the new node ID from the `Location` header or by looking up the node by its key.
    - `TaxoStoreNodeFilter.ancestorKey` is now a single string (it was a string array, while the API accepts a single exact key); documented filter properties and flag match modes (`none` = none of the flags present).
  - `@myrmidon/taxo-store-picker`:
    - the top node (category) filter now restricts lookup to all the descendants of the selected top node, via the API `ancestorKey` filter. It previously used a partial match on the parent key, which matched only direct children, or deeper descendants only when their parent key happened to contain the top node key.
    - `TaxoStoreLookupOptions` has a new `ancestorKey` option.
- 2026-10-03: tests (Vitest) and fixes:
  - added `@vitest/coverage-v8` to allow running tests with `--coverage`.
  - `@myrmidon/taxo-store-api`:
    - `getTree`, `getNode` and `getNodeFromKey` now return `null` when the resource is not found (HTTP 404), as documented, rather than retrying and then erroring.
    - `getNodeFromKey` now URI-encodes tree ID and key.
    - `addNode` now returns the node ID: the API returns an empty 201 response, so the method previously emitted `null`. The ID is now the updated node's ID, or the new node's ID got from the `Location` header (when exposed) or by looking up the node by its tree and key.
    - `addTree` now returns the tree ID (`string`) rather than an always-null `number`.
    - full unit test coverage.
  - `@myrmidon/taxo-store-editor`:
    - `TaxoStoreEditor` now reloads its tree when its `treeId` or `pageSize` inputs change; previously, the tree was loaded only once on init, so e.g. a picker whose tree ID changed kept displaying the old tree.
    - `TaxoStoreEditor` adding a child or sibling node now correctly navigates to the new node (this was broken because `addNode` always returned `null`, see above).
    - `TaxoStorePagedTreeService` normalizes the `null` parent ID returned by the API for root nodes to `undefined`, as expected by `TreeNode`.
    - `TaxoStoreNodeFilter`: added accessible names (`aria-label`) to icon buttons.
    - unit tests for all components and services.
  - `@myrmidon/taxo-store-picker`:
    - `TaxoStoreLookupService.getById` now correctly handles keys containing dots (e.g. `animals.animal.bird` is tree `animals`, key `animal.bird`); previously the key was truncated at its first dot.
    - `TaxoStorePicker` now resets the selected top node (category) filter when the tree ID changes, as it belongs to the previous tree, and ignores stale top nodes responses.
    - `TaxoStorePicker`: added accessible names (`aria-label`) to icon buttons, and `aria-expanded` to the tree editor toggle.
    - full unit test coverage.
  - `@myrmidon/cadmus-part-taxo-store-nodes`:
    - `TaxoStoreNodesPartComponent`: for a new part, the tree ID is now got from the part's role ID in the editor identity; previously it was empty, so no node could be picked in a new part. The `treeId` property is now a computed signal (part's tree ID, else part's role ID, else identity's role ID).
    - `TaxoStoreNodesPartComponent`: added accessible names (`aria-label`) to icon buttons.
    - unit tests for all components. Note: `@myrmidon/cadmus-item-editor` imports packages which are not installed in this workspace (e.g. `@myrmidon/cadmus-ui-flag-set`), so its module is mocked in tests.
  - fixed stale peer dependency ranges among workspace libraries (e.g. `@myrmidon/taxo-store-api: ^0.0.2` while its current version is 1.x; `@myrmidon/cadmus-core: ^12.0.4` while the workspace uses 13.x).
  - app: migrated legacy (Karma-era) smoke specs to zoneless Vitest (removed `waitForAsync`, which requires zone.js; fixed a renamed class import; added router and HTTP testing providers).
- 2026-09-06: updated packages.
- 2026-06-11: upgraded to Angular 22.
